# 股票联动性与股性：实现与行为说明

## 产品定位与页面协作

日常采集已作为独立 `end-of-day-events` 盘后子任务接入现有归档体系；首次历史回补仍由用户显式手动触发。现有实时行情、盘后行情和成份同步的开关保持原状。手工采集命令继续作为回补/修复入口，不是日常调度的替代。

“股票联动”入口承载一个股票研究工作区，而不是与现有页面分离的一份行情软件。中心对象是一只股票，始终显示股票代码、研究截止日、统计窗口、市场范围和实际样本覆盖。工作区由三个部分组成：

| 部分 | 回答的问题 | 主要内容 |
| --- | --- | --- |
| 联动性 | 这只股常与哪些股票同时出现相同事件？ | 同日涨停、同日触涨停、同日跌停三种网络；关联排名、双向条件共现率、基准频率、共同日期 |
| 股性 | 这只股自身的触板与封板行为如何？ | 触涨停、封板、炸板、回封、跌停、触涨停后跌停次数；已知开板次数、首次触板时间与板型 |
| 事件回看 | 上述统计由哪些实际记录得出？ | 按日显示所属池、首末时间、开板次数、几天几板源标签和原因；从共同日期直接核对证据 |

完整研究页顶部另有“今日涨停核心”按钮。它不改变上方“截止日期”的历史研究上下文，而是在点击时单独读取一次同花顺当前仍封住涨停的实时成员，优先用这些成员过去一年积累的同花顺 Top20 题材标签实时识别多条题材主线；没有有效历史标签的成员才使用本地东财概念/行业关系兜底。再结合历史收盘封板关系把今日未封板的股票列为“外溢待选”。后台仍为每条主线独立排名以计算候选交叉，但面板只展示去重后的统一候选结果集，每只股票只出现一次。历史关系和题材标签严格截止到今日之前最近一个完整归档日，今日盘中快照不写入 `limit_up_day`，也不进入历史分母。面板显示快照时间、当前封板数、历史截止日、完整历史样本日、各成员历史封板/触板天数、题材标签、按核心度排序的关系表、实时主线摘要和统一候选结果；可调整历史回看、市场范围、最少共同天数、Top 核心数和候选结果数，也可手动刷新快照。默认不自动轮询，因为盘中封板池会随开板、回封变化。

今日核心的历史关系只使用“同日收盘封板”事件，与完整研究页的 `event=seal` 口径一致；炸板和跌停天数仅作为今日成员的历史股性展示，不进入关系边。核心度是可复现的展示排序分：`100 × (35% 关系强度 + 25% 关系覆盖 + 20% 邻居强度 + 20% 同题材聚类)`，四项在本次今日成员子图中各自按最大值归一化；没有有效题材标签时题材项为 0，其余三项重新归一化。关系强度是与该成员相连的所有收盘封板边的热度折算共现之和；关系覆盖是有有效关系的今日成员数除以今日封板总数减一；邻居强度是相连成员自身关系强度的汇总；同题材聚类是与今日其他成员共享有效题材标签的 IDF 加权强度。个股优先使用同花顺 Top20 历史标签；没有有效历史标签时，使用本地东财概念/行业关系兜底。该分数只在当前快照成员内部有排序意义，不是全市场中心性，也不代表因果、带动能力或收益预测。外溢待选采用两阶段：先为每条实时主线独立排出历史候选并保留交叉，再只为多主线候选并集批量读取盘中行情和暗盘 tick；面板最终只展示去重后的统一结果集。单主线贴合 = `主线权重 × (o+r)/(o+r+2)`（o 为历史出现次数，r 为近60日出现次数），跨主线共振 = `1 - Π(1 - 单主线贴合)`；有行情时候选分 = `100 × (30% 盘中承接 + 40% 主线项 + 20% 历史特异性 + 10% 关联覆盖)`，统一表使用多主线共振分，风险最多折价 15%；行情不可用时实时项退出、其余项重新归一化并明确标记“仅历史观察”。历史特异性对每条候选-成员边计算 φ 相关系数 `(oN - sm) / sqrt(sm(N-s)(N-m))`（o 为共同封板天数、s 为候选封板天数、m 为今日成员封板天数、N 为历史完整日数），负数截零，再乘以 `1 + 今日成员核心度/100` 和样本置信度 `o/(o+2)`，取最强 3 条边的均值；因此封板次数多但并非专门跟随今日核心的股票不会天然占优，单次共现也不会被放大。盘中承接 = `启动承接30% + 剩余空间20% + 换手自身历史分位15% + 量比10% + 主力资金自身历史分位10% + 暗盘资金自身历史分位15%`，已触板未封扣 20%，不奖励接近涨停；换手、主力和暗盘资金使用个股最近20个交易日同一5分钟时点的自身历史分位，量比直接使用东财自身基准值，不拿不同股票横比；风险扣分 `risk_penalty` 逐行展示，综合分只做最多 15% 折价。今日题材主线取今日封板成员共享的有效题材标签，至少 2 只成员共享才计入，按成员核心度和标签 IDF 加权；时效 = `e^(-Δt/90) + (1-e^(-Δt/90)) × n/(n+5)`，`Δt` 是当前封板成员最近一次封板（回封也算）距快照的交易分钟数，午休不计入；`n` 只统计当前仍封板且共享该题材的成员，不含未涨停或炸板股；封板质量 = `封板/(封板+0.5×炸板+1×跌停)`，炸板、跌停取实时侧池；每条主线分别保留，不用最强80%+次强20%合并；“其他概念”“未分类”“原因不明”或全组没有明确原因的题材桶不参与。历史标签的最近出现日期不参与权重。只通过题材标签关联、没有直接共封边的候选会保留 `effective_links=0` 和 `strength=0`，不会伪装成强历史关系。股票自身近一年涨停次数不直接加分，外溢待选也不是买卖建议。

关系图以选中股票为中心，只展示最相关的一组邻居。点击邻居切换中心，保留截止日和窗口。图只是索引，精确指标和共同日期放在关系表中；不把连线或高提升倍数直接称为“龙头带动”或买入信号。

跨页协作按以下契约实施，不让每个页面分别计算一套口径：

| 现有页面 | 协作方式 | 日期与数据边界 |
| --- | --- | --- |
| 今日监控 | 板块成分股行提供“联动/股性”快查（Top 5/10）并可进入完整研究页；板块仍在原监控页展示 | 盘中研究只用此前已完成的事件归档，明确显示样本截止日；实时行情不直接改写股性。板块代码不能当股票代码传入 |
| 收盘个股 | 个股行提供“联动/股性”快查并可进入完整研究页；研究上下文继承所选收盘日期。现有事件明细与共同日期可查看，点击事件日期跳回收盘个股尚未实现 | 继承所选收盘日期，不悄悄切到今天；行情缺失时仍能研究事件，但明确提示无该日行情 |
| 历史回看 | 保持原板块历史功能；与股票联动的历史截面联动尚未接入 | 后续接入时使用历史截面日期及当时成员关系；不拿最新成份解释过去，盘中历史视角不提前使用当天收盘事件 |
| 动态筛选 | 个股结果已提供“联动/股性”快查和完整研究入口；把本地封板率、炸板率、跌停频率等作为筛选条件尚未实现 | 不改变现有筛选策略默认值；后续条件使用同一截止日，缺事件数据时标记不可判断，不视为满足或为零 |
| 采集质量 | 已增加“涨跌停事件归档”只读分项，显示三池数量、交易日、采集时间、完整性及失败原因 | 区分未启用、未采集、运行中、失败、完整且零只；已完成事件归档不依赖东财行情/资金是否完整 |

今日监控的板块成分股表直接展示近 365 自然日的收盘涨停、触板、炸板、封板率和跌停天数，默认按收盘涨停次数降序。统计以板块当前截面日为截止日，只使用本地涨停、炸板、跌停三池完整归档日，未采集日不补零；接口同时返回实际归档首末日和完整样本日数，归档不可用时不允许把缺失当成 0 次。封板率 = 收盘涨停天数 / 触板天数，跌停天数独立统计，不进入上涨侧分母。

今日监控的板块成分股、动态筛选的个股结果和收盘个股行均已接通股票快查：默认回看 365 自然日、市场范围 `HS,GEM2STAR`、最少共同 1 次，可在弹窗内调整回看周期（30/90/180/365 自然日）、市场范围、共现事件、最少共同次数（1..10）及 Top 5/Top 10，并显示实际样本截止日。快查联动结果按共同次数降序，其次按热度折算共现和代码稳定排序；完整股票联动页仍保留其原有的默认排序。快查可进入完整股票联动页；完整页 URL 保存 `view=linkage`、`source`、`stock_code`、`stock_name`、`as_of`、`days`、`scope`、`event`、`min_overlap`，其中 `source` 为 `monitor`、`focus` 或 `stocks`，仅用于标记和从完整页返回。返回沿用来源页已保留的页面状态：今日监控恢复板块分页并滚动到成分股，动态筛选恢复滚动位置；收盘个股保持已选日期。来源页的搜索、排序和筛选表单本身不存入此研究 URL。

从研究页查看采集质量时，同时携带研究截止日与市场范围，避免把默认范围的完整归档误作扩展范围的数据覆盖。质量页允许只读切换“后端默认范围”“沪深及双创”“含 ST、未开板新股”，不同口径独立查询和缓存。事件质量卡不依赖资金/行情质量查询成功；已有完整版本而最近一次重采失败时，同时显示“三池完整”和失败提示，保留旧版可用性与失败证据。

统一研究上下文为 `stock_code + as_of + days + scope + event + min_overlap`，完整页按上述 URL 参数保存，支持刷新、分享和浏览器返回。完整页提供候选股票搜索和六位代码手输；入口选定或手输的股票即使在窗口内无事件，也必须保留该股票并显示“当前范围无事件记录”，不能自动跳到另一只股票。只有默认进入研究首页且没有指定股票时，才可选择榜单中的首个候选。

同花顺与东财通过规范化股票代码/交易所身份关联，不直接互用两家的 `market_id`；该身份映射只用于行情、事件和板块读取，不用于把东财行业/概念当作同花顺题材主线。股票名称按对应历史日期显示。完整研究页直接输入支持六位代码、中文名称、拼音首字母和全拼；输入联想只从当前窗口的事件候选生成，六位代码即使不在候选中也保留“无事件”结果。市场范围、ST/新股资格及数据缺口不能因跨页跳转而悄悄改变。

## 盘后归档协作

日常流程为：盘后调度 → 独立 `end-of-day-events` 子任务 → 交易日与三池全量校验 → 原子发布事件归档 → 研究页面读取。任务在交易日 `16:30`、`16:35`、`16:40` 发出邀请，复用持久化任务和运行记录；单次预算 10 分钟，最多 3 次尝试，失败约 1 分钟后重试，已有完整归档时后续邀请只检查存在性并跳过。服务启动时在非盘中窗口恢复最近交易日：交易日 `09:30–16:00` 不恢复，`16:00` 后恢复当日，之前恢复上一交易日。同花顺闭市门槛为 15:30，16:30 批次位于该门槛之后。

- 事件采集是盘后归档的独立分项，使用独立的同花顺客户端，不要求先完成东财资金、日 K、五分钟行情或成份同步。
- 同花顺题材补充由独立的 `ths-focus` 任务在 `16:45` 执行；受限账号数据在 `16:50/17:10/17:50` 执行，二者都在个股五分钟 K 的 `17:00` 归档之前。
- 事件任务使用独立调度 lane，不阻塞分钟、行业/概念/个股资金归档；既有实时、盘后行情和成份开关保持不变。
- 涨停、炸板、跌停三池任一失败，本次事件归档不发布；此前成功版本保留。其它已完成归档分项不回滚，事件失败也不改变原盘中清理条件。
- 事件分项由 `SHADOWFLOW_LIMIT_UP_ARCHIVE_ENABLED` 控制，默认 `false`；只有调度开启、该开关为真，且自身与父级 `end-of-day` 均未被 `SHADOWFLOW_SCHEDULER_DISABLED_KINDS` 禁用时才运行。不能为启用事件归档而顺带开启此前关闭的行情或成份任务。
- 自动运行仅处理日常归档及受限的失败重试，启动服务和打开页面均不发起全年回补。首次回补由用户选择日期范围并手动触发，与日常任务共享同一解析、校验和写入流程。
- 完整性按数据集分别判断：事件完整即可计算本模块；行情未归档时，不展示收益、溢价或分钟先后关系的推算值。采集质量页已按分项显示状态，不把所有来源绑成一个成功/失败开关。

## 第一版范围

以同花顺涨停聚焦的完整日终涨停池、炸板池、跌停池为独立事件源，提供“股票联动”页面中的共现网络和个股股性画像。研究无需等待东方财富日 K、五分钟行情或板块成份恢复。日常增量已接入独立盘后分项，默认关闭；手工命令用于首次回补和修复。服务启动及打开页面不触发历史回补，也不自动补满全年。

实施顺序：

1. 严格分页、完整性校验的同花顺客户端，以及独立事件表。
2. 日级原子发布、幂等重采、按来源和市场范围隔离。
3. 个股共现统计和股性画像的只读 API。
4. 股票选择、关系图、可核对指标与原始事件明细页面。
5. 使用合成边界样本和真实接口样本验收；不自动启动全年回补。

默认市场范围 `HS,GEM2STAR`，另支持 `HS,GEM2STAR,ST,NEW`。两个范围分开存储、分开计算，不混用；尚未验证北交所覆盖，页面不称“全 A 股”。图的连边完全依据同日事件，不按行业、概念过滤。

## 数据契约与完整性

客户端按响应分页总数逐页抓取涨停池、炸板池和跌停池，校验请求日期、交易日确认、总数稳定、单池唯一代码，以及 `limit_up_count.today` 的封板/炸板/累计触板汇总和 `limit_down_count.today.num` 的收盘跌停总数。只有三池全部完成才写入单日快照；真实零事件日需要交易日确认、明确的零总数和空数组。网络失败、错误日期、重复页、HTML 风控页及不完整首屏不得发布。

每个 `(来源, 范围, 日期, 代码, 所属池)` 唯一。涨停池与炸板池互斥，收盘涨停与收盘跌停互斥；炸板池与跌停池可以重叠，保留同股同日两条事件，以表达“曾触涨停后最终跌停”。上侧累计触板数仍等于涨停数+炸板数，不能与跌停数直接相加作为唯一股票总数。跌停池是最终收盘跌停集合，源端 `limit_down_count.today.history_num` 还包含盘中触及跌停后打开的股票，不能替代本池总数。

日终采集只接受历史日期，或当日上海时间 15:30 之后。该门槛依据 HAR 中同花顺 `trade_status.id=closed` 的 15:30 起始时间，当日还须确认源端已收盘状态。股票代码保留前导零；首末时间按 Unix 秒转上海时区；`open_num=null` 保持未知。保存原始 JSON、来源、范围、采集时间和内容摘要；重采在事务内整体替换对应日期和范围，失败保留旧版。原始同花顺年度封板率仅作源记录，不参与本地画像及历史指标。

接口与采集使用独立的读写契约，不依赖日终资金归档是否完整。只读查询仅访问该模块的新表，不扫描五分钟行情表。

## 分析口径

日期范围按自然日回看，默认 90 日，可选 30/90/180/365 日；查询截止日严格限制数据，不使用未来事件。分母 N 只包含范围内已完整采集的交易日；真实空榜单日计入 N，未采集日不计入、不补零。页面展示实际首末样本日期、N 和请求日期范围，不宣称已经覆盖整个范围。个股频率是完整榜单样本日中的事件频率，不是已校正停牌、上市及 ST 资格的发生概率。

### 联动性

可选“同日收盘涨停”“同日曾触涨停”或“同日收盘跌停”。每种事件独立构图，触涨停图不混入仅跌停的记录。对于中心股票 A 和 B，设事件日数为 a、b，共同事件日数为 c：

- 共同事件次数：c；默认最少 3 次，可调为 1 次进行探索。
- 条件共现率：P(B|A)=c/a，反向为 c/b。
- 样本基准频率：b/N；提升倍数 lift=cN/(ab)。
- Jaccard：c/(a+b−c)。
- 二元事件相关系数 phi=(cN−ab)/sqrt(ab(N−a)(N−b))；常量序列返回 null。
- 热度折算共现：每个共同事件日贡献 1/max(1,当天相同事件池规模−1)，降低大面积普涨日的单次贡献。默认按此值、共同次数及代码稳定排序；它不是完全市场中性的相关系数。

只为选中的中心股票即时计算邻居，不逐日物化全市场所有股票对。默认返回前 30 个，API 上限 100。少于 20 个完整交易日或少于 3 次共同事件标记样本不足；20/3 是展示门槛，不代表显著性检验通过。共现关系不能证明先后带动、因果或未来收益；本版不提供涨跌预测。

### 股性

分别统计触板日、收盘封板日、最终炸板日；本地封板率=封板日/触板日。开板次数仅在非空记录中求平均，单列未知天数。已知曾开板日包含炸板池及收盘涨停但正开板次数的样本；最终回封日为后者，回封率分母仅为已知曾开板日。首次触板时刻提供有时间戳样本数、中位时刻和时段分布。板型和“几天几板”保留源标签，“5天4板”不转成“4连板”。

上述触板、封板、开板、回封和时段分布均指涨停侧。另统计收盘跌停日、样本跌停频率（跌停日/完整样本日）和触涨停后收盘跌停日（炸板池与跌停池交集）。仅出现在跌停池的股票仍可选择，上涨侧封板率、平均开板次数等无分母指标返回 null。跌停源的首次/最后时间为空时保持未知；不凭空推算下跌开板率、地天板或跌停回封。

后续再做交易日历严格验证的连板序列、T+1/T+3 溢价、收益相关、分钟先后关系和样本外评估；这些需要行情、公司行动和上市/停牌历史，不能从现有事件列表或 80 点预览推导。

## API 契约

- `GET /api/v1/limit-up/quality?trade_date=YYYY-MM-DD&scope=HS,GEM2STAR`：只读事件归档状态，返回 `scheduled`、`status`（`disabled`、`not_collected`、`running`、`failed`、`complete`）、三池数量、最近一次运行和最近完整日期。
- `GET /api/v1/limit-up/overview?as_of=YYYY-MM-DD&days=90&scope=HS,GEM2STAR`：覆盖信息、每日三池数量和出现过的股票。
- `GET /api/v1/limit-up/stocks/{code}?as_of=YYYY-MM-DD&days=90&scope=HS,GEM2STAR&event=seal&min_overlap=3&limit=30&order=heat`：覆盖信息、股性、全市场同日共振、同花顺历史题材画像与同题材联动、共同日期及中心股票事件记录。`theme.profile.tags` 是历史累积 Top20 多标签；`theme.links` 是同题材联动。`order=overlap` 只影响全市场共振表，不改变题材聚类排序。
- `GET /api/v1/limit-up/today-network?days=365&scope=HS,GEM2STAR&min_overlap=1&top=5&candidates=20`：点击时实时读取当前封板池、炸板池和跌停池，用今日之前历史窗口内的同花顺 Top20 累积标签计算多条 `theme_mainline`，并返回今日成员、核心排名、各核心关系、`mainline_candidates` 多主线候选组、`mainline_intersections` 主线交叉及历史覆盖。`candidates` 是每条主线各自的候选上限，同一候选可出现在多个组。单主线贴合 = `主线权重 × (o+r)/(o+r+2)`（o 为历史出现次数，r 为近60日出现次数），跨主线共振 = `1 - Π(1 - 单主线贴合)`；候选分在有行情时为 `30% 盘中承接 + 40% 主线项 + 20% 历史特异性 + 10% 关联覆盖`，盘中承接 = `启动承接30% + 剩余空间20% + 换手自身历史分位15% + 量比10% + 主力资金自身历史分位10% + 暗盘资金自身历史分位15%`，已触板未封扣 20%，不奖励接近涨停；换手、主力和暗盘资金使用个股最近20个交易日同一5分钟时点的自身历史分位，量比直接使用东财自身基准值，不拿不同股票横比；风险最多折价 15%，`risk_penalty` 逐行展示实际扣分。无候选行情时明确返回 `live_candidate=false` 并降级为历史观察。主线时效使用当前封板成员的最近封板时间和当前封板宽度 `n/(n+5)`，`n` 只含共享该题材的当前封板成员；封板质量按当前炸板/跌停成员扣减。只通过题材标签关联的候选保留 `effective_links=0`、`strength=0`。`meta` 明确 `snapshot_only=true`、`history_excludes_today=true`、快照时间、`live_quote_status` 和 `live_dark_money_status`。今日之前没有完整归档时仍返回实时成员，但 `history_available=false` 且不伪造关系。

`event` 支持 `seal`（涨停）、`touch`（触及涨停）和 `down`（跌停）。接口路径保留数据源的 `limit-up` 命名，响应的 `down_count`、`down_days` 和 `down_frequency` 为独立跌停指标。

沿用现有 Bearer 鉴权、速率/超时限制；请求范围限制 1..366 自然日。空库返回真实空状态，不注入演示股票；所选股票在窗口内无事件返回明确的未找到结果。

`overview` 与 `stocks` 同一时刻最多一个研究查询，使用独立并发槽，限制单次最多读取 15 万条事件；超过时需要缩小日期范围。查询使用 SQLite 一致性读事务，避免并发重采时读到不同版本的汇总和事件。`quality` 只读汇总和最近运行记录；完整版本存在时，即使后续重采失败，仍返回 `complete` 并附失败运行记录。

`as_of` 截止的是事件交易日。当前表保存最近一次成功采集的版本，历史修订不等于当时可知信息；第一版不承诺点时回测数据。原始页与内容摘要随当前版本保存，后续需要点时回测时再增加不可变修订历史。

## 手工采集与使用

在 `backend` 目录运行，写入现有 `SHADOWFLOW_DATABASE_PATH` 指定的数据库：

```bash
go run ./cmd/collect -task limit-up -date 2026-11-05
go run ./cmd/collect -task limit-up -date 2026-11-05 -scope HS,GEM2STAR,ST,NEW
```

当前手工命令先打开 `SHADOWFLOW_DATABASE_PATH` 并写入一条 `running` 运行记录，再使用独立的低频 HTTP 客户端串行抓取三池（默认每页至少间隔 1 秒）；不需要登录凭据，不触发东财采集、代理预热或成份同步。三池响应日期、汇总计数、分页和唯一性全部验证通过后，才在单事务内原子替换该日期与范围的完整版本。抓取或校验失败时返回非零退出状态，旧完整版本不删除，失败运行记录保留。每次命令只处理显式指定日期，不自动补满一年。该命令是手工回补/修复通道，日常采集由独立盘后子任务执行。

启动 Web 后进入“股票联动”，选择日期范围、市场口径及股票；“重新读取”仅查询本地已采集数据。今日监控成分股、动态筛选个股和收盘个股也可直接打开 Top 5/Top 10 快查；采集质量页的“涨跌停事件”分项读取只读 quality API。开发验收可用另一个数据库路径隔离样本，不写入现有运行库。

## 验证边界

本轮已用内存 SQLite 合成样本和正式分析 API 验证“监控成分股 → Top 5/10 快查 → 完整研究页”、涨跌停口径切换、同花顺 Top20 多标签画像、未分类题材桶过滤、同题材日去重、题材候选零共封标记、关系图键盘切换中心股、返回来源、Esc 恢复焦点、无事件保留所选股票，以及研究到质量页的日期和范围传递。320px/390px 页面无整页横向溢出，表格在自身容器内滚动。合成数据仅用于开发验收，不能视为真实历史覆盖或实盘统计效果；未部署。
