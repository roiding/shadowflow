# 最小量化训练框架：先固定收益，再训练模型

日期：2026-11-14。定位：离线研究原型；本目录不连接生产库、不自动采集，不是下单系统。`label_core.py` 使用 Python 标准库；训练脚手架需要单独安装依赖。价格、公司行动、证券资格等真实数据适配器尚未接入。

## 1. 第一版只回答一个问题

在交易日 **t 的盘后数据实际可用后**产生信号，以 **t+1 开盘**为入场价格基准，以 **t+6 开盘**为退出价格基准，预测这五个交易日区间的税费前持有财富收益。`h=1` 对应 t+1 开盘至 t+2 开盘，遵守 A 股买入次日才能卖出的约束。t+n 必须通过交易所日历定位。

这一定义不把盘后才取得的资金、题材用于 t 日收盘成交。日终字段用于第二天决策；今后做盘中模型时，另建盘中可用性契约。

训练目标是估值收益。涨停无法买入、跌停无法卖出、开盘成交量不足等属于执行层；即使目标时点有开盘报价，也不能宣称可以按此成交。原型保留 `entry_blocked/exit_blocked/unknown` 标志，不以这些未来状态筛选 t 日候选。真正组合回测必须另行模拟成交、持仓和现金。

## 2. 固定收益口径

本版采用“现金分红不再投资”的公司行动账本，避免把某家软件的前复权图形算法直接当成账户收益。

开始持有 q=1 股，现金/应收股利 c=0，入场未复权价格为 O_entry。每个持有期内的除权日，按**事件发生前持股数**计现金分红，再调整持股数：

```text
c <- c + q * cash_per_old_share
q <- q * share_multiplier
y = (q * O_exit + c) / O_entry - 1
```

只处理 `entry_date < ex_date <= exit_date`：除权日开盘才买入，不享有该次权益；持有至除权日开盘则已享有。现金在除息日按应收股利计入财富，不假装实际派息日已到；派息税、现金再投资和资金占用在后续执行账本单独处理。

| 案例 | 未复权价格变化 | 账本结果 |
| --- | --- | --- |
| 普通上涨 | 10 → 11 | +10% |
| 每股派 1 元，除息后价格 9 元 | 10 → 9 | 9+1=10，0% |
| 一股变两股 | 10 → 5 | 2×5=10，0% |
| 一股变两股且每旧股派 1 元 | 10 → 4.5 | 2×4.5+1=10，0% |
| 每股派 1 元，后来价格 9.9 元 | 10 → 9.9 | 9.9+1=10.9，+9% |

最后一行不能直接用 `9.9/9-1=10%` 替代；后者是相对除息参考价的市场涨幅口径。两者目标不同。

另一条合法研究路径是使用**已认证、同供应商、同算法、同快照**的乘法复权因子：

```text
y_adjusted = O_exit * A_exit / (O_entry * A_entry) - 1
```

目录中的 `factor_return()` 只提供这条辅助计算，不将它冒充现金不再投账本收益。Tushare 的复权说明明确采用“分红再投”；前复权 `P*A/A_anchor` 和后复权 `P*A` 在同一乘法体系内计算端点收益时锚因子会约掉。但不同网站的加减式复权、舍入和再投资约定可能不同，不能凭“前复权”三个字混用。**对复权因子收益再加一次现金分红会重复计入权益。**

首版支持已核实的现金分红、拆合股/送转的财富变化。配股、换股、分拆、合并、退市清算、特殊资本重组返回 `unsupported_corporate_action`，不填零。送股到账时间、零股处理、现金税额和可交易股数仍需执行层处理，因此本函数不是完整账户回测器。

## 3. 最少输入表及其契约

| 表/文件 | 必须保留的内容 | 约束 |
| --- | --- | --- |
| 交易日历 | 市场、真实交易日序列、版本、来源 | 不由本地有数据的日期生成 |
| 证券历史 | 交易所+代码、上市/退市日、历史 ST/停复牌/涨跌停规则 | 不能拿今天的存活股票作为全部历史股票池 |
| 日行情 | 原始 OHLC、成交量（股）、金额（元）、参考前收、来源、可用时间、调整模式、契约验证状态 | 原始价格与行情参考前收分开；换源先认证 |
| 公司行动 | event_id、公告时间、登记日、除权日、派息日、现金/旧股、股数倍数、配股等类型、来源、版本 | “每 10 股”先转换为每旧股；同日事件先合并；无记录不等于无事件 |
| 公司行动覆盖清单 | security、覆盖首末日、complete、verified_at、版本 | 没有完整覆盖证明就不生成有效标签 |
| 复权因子（可选） | security、日期、因子、供应商算法、锚点、版本 | 用于连续价格特征/交叉核对，不直接作为数值特征 |
| 研究事实（第二阶段） | 资金、事件、分类、关系快照及 available_at | 盘后修订、后来回补的分类不能冒充当时盘中已知 |

需要区分 `event_time/有效日期`、`source_published_at`、`first_observed_at`、`available_at`。历史回补若没有原始发布时间，记录 `availability_basis=reconstructed`；不能为了通过时间检查虚构当时可用性。回补研究和真实逐日前向验证分别报告。

`Price.contract_verified` 默认是 false，必须由适配器完成身份、日期、未复权模式和单位验证后显式开启。价格改正、公司行动改正都生成新的冻结数据集，重建受影响标签；原训练包保留。

## 4. 模块与运行方式

```text
供应商原始响应
  -> 身份/单位/日历/公司行动校验
  -> 冻结事实包（dataset_id + 原文件 SHA256）
  -> label_core.make_label（真值）
  -> 特征构造（仅信号时点可用数据）
  -> 按日期分割及清除跨边界标签
  -> LightGBM
  -> 冻结模型、预测、指标
  -> 独立执行回测与前向观察
```

标签引擎与金融边界测试无需安装额外库：

```bash
python3 -m unittest discover -s docs/quant-minimal-2026-11-14 -p 'test_*.py' -v
python3 docs/quant-minimal-2026-11-14/label_core.py
```

第二条仅演示虚构的 10→5、股数翻倍案例，预期 `y=0`、`raw_price_return=-0.5`；不会训练或读取真实股票。

调用 `make_label()` 时，传入按交易所日历排列的 `date`、按 `(security, trade_date)` 索引的 `Price`、该证券公司行动列表、覆盖清单，以及冻结包 `dataset_as_of/dataset_id`。结果中的 `y=None` 必须与明确的 `status` 一起保存。用 `Label.jsonable()` 得到适合转为 CSV/JSON 的记录。

训练输入 `features.csv` 的列必须**恰好**为：

```text
dataset_id,security,signal_date,signal_at,feature_available_at,eligible_asof,
ret_1d_adjusted,ret_5d_adjusted,ret_20d_adjusted,volatility_20d,
log_amount,amount_ratio_20d,turnover_pct,amplitude_pct
```

`labels.csv` 至少包含：

```text
dataset_id,security,signal_date,entry_date,exit_date,horizon,
label_version,action_version,status,y,label_ready_at
```

两个文件的 `(dataset_id,security,signal_date)` 唯一。标签 y 是小数，0.05 表示 5%；时间戳必须显式带时区；`eligible_asof` 只用信号时点的证券资格，不用未来涨跌或成交状态。公司行动账本标签版本为 `cash-nav-next-open-v1`。

`calendar.json` 包含 `{"trading_dates":["2026-11-02", ...]}`，同时建议保存交易所和版本等附加字段；必须覆盖训练起点之前的特征窗口和最后信号之后的全部目标日期。

在研究机器的独立虚拟环境准备依赖后，运行：

```bash
python3 -m venv .venv-quant
.venv-quant/bin/python -m pip install -r docs/quant-minimal-2026-11-14/requirements.txt
.venv-quant/bin/python docs/quant-minimal-2026-11-14/train_lightgbm.py \
  --features /path/to/frozen/features.csv \
  --labels /path/to/frozen/labels.csv \
  --calendar /path/to/frozen/calendar.json \
  --as-of 2026-11-14T10:00:00+08:00 \
  --output /path/to/new-model-run
```

依赖文件是兼容范围；每次模型运行记录实际版本。正式可重复环境还应固定 wheel/依赖锁文件。训练在研究机器离线进行，N1 继续负责有限采集和服务。

本轮验证环境的确切 Python 包版本保存在 [requirements-tested.txt](requirements-tested.txt)，为 CPython 3.9.13/macOS x86_64，并使用机器已有 libomp；其他平台应重新验证相应运行库。

脚手架不会替用户选择价格/公司行动供应商，也不会自动把现有 `future-returns-v1` 改名后当作新标签。输入适配和特征构造是接入真实数据前必须完成的步骤。

## 5. 第一版特征与模型

默认从八个简单价格/量额特征开始，不让修复中的五分钟字段拖累标签验证：

- 1/5/20 日连续价格收益；算法、因子快照和可用性固定。
- 过去 20 日连续日收益的标准差。
- 日成交额的 log1p、相对过去 20 日成交额均值之比。
- 已认证的日换手率、相对当日参考前收的日振幅。

价格收益、波动率的滚动窗口不能用缺档后的“最近若干条”代替连续交易日；特征缺口保留 NaN。每股的调整后量价关系需统一，实际成交金额和原始主力/暗盘金额不直接乘复权因子。树模型不强制做跨全样本标准化。

第二阶段才增加：历史封板/炸板统计、当时可知的题材强度、日主力净流入/日成交额、日暗盘净流入/日成交额、末段资金增量/同口径成交额。先修复本次审计发现的单位和累计/区间混用。新增特征必须在完全相同的样本外日期上与八特征基线比较。

模型使用固定的小型 LightGBM 回归：15 叶、深度 4、学习率 0.03、每叶至少 200 样本、L2 正则。模型参数只是起点；不先做大规模调参。每天总样本权重相等，避免证券数量多的日期占更大权重。现有配置示例训练 2024 年起至 2026 年 4 月，验证 5–7 月，测试 8 月至 11 月 5 日；后者五日标签可在 11 月 13 日到期。

**当前生产只有 33 个 `daily_feature_set` 日期，不能因为每天下面有五千只股票就宣称拥有足够长期样本。**示例要求训练至少 252 个信号日，验证和测试各至少 40 日；这些是研究门槛，不是统计显著性保证。可先从独立日行情补足 2–3 年建立价格基线；只有较短历史的暗盘特征另做前向增量实验。

## 6. 分割、成熟度与防止泄漏

1. 同一信号日所有股票进入同一分区，禁止随机拆行。
2. 训练集标签必须在验证开始前已经结束且已经可知；验证集标签在测试开始前满足相同条件。代码同时检查 `exit_date` 和 `label_ready_at`。
3. 重新用外部交易日历核验每个标签的 entry/exit，不只相信 `horizon=5` 这个整数。
4. 超参数和早停只看验证集。测试集只执行一次评估，不能反复选择特征后继续称原测试集“未见”。
5. 第一版前后相邻的纯前向分割，边界清除跨区间标签即可。后续使用双向交叉验证才需要另行定义 embargo；不要把固定“空五天”当作适用于所有持仓周期的万能措施。
6. 训练前拒绝未来特征、混合数据集 ID、混合标签版本、重复证券日期、无时区时间、无穷值，以及周期不符的标签。覆盖率不通过直接停止，不截尾掩盖除权异常。
7. 无法生成标签的退市/停牌/公司行动样本按原因统计。缺失通常不是随机的；即使整体覆盖超过 98%，仍要按时间、行业、ST/退市分组检查。部署候选不能使用“未来能否取得退出价格”这个条件。

默认 `availability_mode=strict_vintage`，标签核心把公司行动覆盖的核验时间计入 `label_ready_at`。因此，今天才首次核验的历史真值不能被这个模式假装成几年前已经可用；首次回补后遇到“可训练日期不足”可能正是这道门槛在起作用。

如果先做通常的历史回溯研究，可以明确设为 `reconstructed_research`：仍清除跨分区的未来收益区间、仍要求全部真值在冻结包时间前可知，但不宣称掌握每个历史训练时点的旧标签版本。输出会记录此模式及限制。特征依然必须按可解释的历史信息发布时间构造；若只能依据收盘时间等假设重建，应在数据集说明里明示，尤其不能用盘后整理的分类回放当天盘中。这种研究和真实逐日留存的前向评估不能合并成一个“无泄漏实盘回测”结论。

## 7. 验证与交付物

标签测试覆盖普通上涨、现金分红、送转、同日现金+送转、分红先后顺序、入场/退出除权边界、交易日缺口、未知公司行动、配股、重复事件、复权重复使用、因子快照混用、T+1、标签成熟度和被涨跌停阻碍的执行标记。

真实数据验收至少抽取 20–30 次公司行动，逐笔核对公司实施公告、原始价格、参考前收、现金和股数变化。检查除权前后标签分布及极端值；区分真实大跌与复权错误，不能把所有异常大收益统一 winsorize 掉。

训练输出包含 `model.txt`、`test_predictions.csv`、`metrics.json` 和冻结配置。记录输入 CSV、日历、标签代码、训练代码、配置的 SHA256、数据集 ID、标签版本、依赖版本、样本覆盖、各分区日期数及早停轮数。

最小诊断指标为验证/测试的 MSE、相对于训练均值常数模型的 MSE、MAE、逐日 Rank IC。五日标签互相重叠，不能把每日 IC 当作独立样本直接算漂亮的 t 值；后续用至少持有期长度的时间块 bootstrap/HAC，并报告置信区间。

进入策略判断前，还需要与等权可交易基准、价格特征基线、仅题材规则做同区间比较；用真实日期版本的交易费用、100 股整手、滑点、现金分红税、开盘成交量参与率、涨跌停/停牌限制和未成交延续持仓计算组合结果。分层收益、换手率、回撤、年度/行情分段稳定性都比一次训练精度更重要。

本目录的验证证明参考实现能遵守其声明的输入和收益契约，不证明真实公司行动源已补齐，也不证明存在可盈利模型。

本次实际结果：22 个标签测试全部通过；[训练流程验收](training-verification.json) 使用虚构价格路径完成真实 LightGBM 训练、验证/测试预测及模型保存，并检查未来特征拒绝、错误 horizon 拒绝、严格版本模式拒绝后来才知道的真值，以及回溯研究模式的明确标注。合成分区有 289/74/81 个训练/验证/测试信号日。这些天数来自测试夹具，不是生产数据覆盖，也不应引用其模型指标作为投资效果。

可在已准备依赖的解释器中运行 `verify_training_scaffold.py` 重现流程检查。初次安装的 NumPy/Pandas/LightGBM 原生库在本机冷启动较慢，首次流程曾在依赖导入阶段超时；依赖加载完成后，最终完整流程通过，没有将那次超时算作成功。
