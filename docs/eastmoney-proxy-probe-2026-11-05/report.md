## 请求与校验口径

业务路径为：本机 macOS → 领取到的 HTTP 代理 → CONNECT → 东方财富 HTTPS。最终成功实验没有固定目标 IP，也没有传入业务 Cookie、登录信息或关闭证书校验，没有直连兜底。

请求接口：`https://push2his.eastmoney.com/api/qt/stock/kline/get`。

- 日线：`klt=101`，`fqt=0`，`beg=20261026`，`end=20261105`，核对这段时间内 9 个交易日。
- 五分钟：`klt=5`，`fqt=0`，`beg=end=20261105`，核对 `09:35–11:30`、`13:05–15:00` 的完整 48 个时间点。
- 使用与现有历史五分钟请求一致的 `fields1/fields2`、`Accept: application/json`、`User-Agent: Mozilla/5.0 ShadowFlow/0.1` 和东财行情 Referer。
- 单行情请求总预算最多 12 秒，连接及握手预算 6 秒；始终受剩余租约时间约束。
- 行情任务串行，任务间隔 3 秒；一个任务最多进行 3 轮领取/请求尝试。
- 成功必须同时满足：HTTP 200、`rc=0`、股票代码及市场匹配、根数正确、日期/时间序列完全一致、OHLC 关系正确、数值有限、量额非负。
- 最终 24 次成功的 HTTP CONNECT 均返回 200，目标 TLS 验证结果均为 0。

日志记录了首尾 K 线、根数、校验结论、响应 SHA-256、匿名连接指纹和分阶段耗时。未将完整行情写入生产归档。

## 按 proxy_pool 规范使用预热、租约和会话

运行服务报告版本为 `listfix2-20261105-e4dd765f6785`。使用既有 `default` 项目，没有创建或轮换项目 Key，也没有修改来源定义、全局限额或生产采集配置。测试只选择公开列表来源，没有调用已启用的 SCDN 取号接口，也没有调用注册或购买流程。

最终预热请求：

```json
{
  "count": 3,
  "timeout": 60,
  "source_ids": ["proxyscrape-elite"],
  "validation": {"mode": "tls", "target": "push2his.eastmoney.com:443"}
}
```

最终领取请求：

```json
{
  "count": 1,
  "timeout": 30,
  "cd": 300,
  "mode": "sticky",
  "session_id": "<本次运行生成并保持不变的会话 ID>",
  "source_ids": ["proxyscrape-elite"],
  "validation": {"mode": "tls", "target": "push2his.eastmoney.com:443"}
}
```

关键流程：

- 预热：`POST /api/v1/prewarm`，通过 `GET /api/v1/jobs/{id}` 查看当前 Ready。
- 领取：`POST /api/v1/proxies/acquire`。已交付的租约默认 30 秒，逻辑绑定默认 10 分钟，两者不是同一期限。
- 健康续租：关闭本轮连接并释放旧租约，再用原会话领取。原会话可以在自身项目 CD 内合法复用绑定，其他会话和普通领取没有这个例外。
- 业务失败：`POST /api/v1/leases/{id}/feedback`，记录失败阶段；释放租约并 `DELETE /api/v1/sessions/{id}` 释放本次自己的失败绑定，然后使用同一逻辑会话重新领取其他合格代理。
- CD：保持 300 秒的新分配窗口；没有通过换项目、换 Key、降低 CD、修改库存或回滚状态取得旧连接。

本次通过现有服务器 SSH 连接读取控制面凭据，在内存中使用；日志没有保存控制面 Token、原始代理地址或代理凭证。这是默认项目的管理授权测试，正式下游仍应使用自己的项目 Key。

## 前置对照和失败实验

| 实验 | 有效行情结果 | 观察 |
| --- | --- | --- |
| 直连基准 | 4 次请求中前 2 次成功、后 2 次空响应 | 重现用户描述的先成功、后连续失败模式；不是固定“两次阈值”的证明 |
| 普通领取，混合公开来源 | 触达 4 个任务，2 成功；实际 5 次行情尝试 | 换代理救回一次日线；随后超时、TLS 失败，以及连续取不到合格代理 |
| 普通领取，固定解析出的目标 IP | 触达 2 个任务，0 成功；实际 1 次行情尝试 | 仍有代理 CONNECT 403；没有证据表明固定 IP 解决问题 |
| 普通领取，单一 ProxyScrape 来源 | 触达 5 个任务，3 成功；实际 4 次行情尝试 | 好代理连续成功 3 次后因租约临近到期被释放，换入代理 CONNECT 403，此后供给不足 |
| 保持健康会话并续租，失败后换代理 | 三轮 24 个任务全部成功；实际 25 次行情尝试 | 一次超时自动恢复，之后同一连接连续成功 23 次 |

前三个普通领取实验均计划 24 个任务，但在连续三次没有取得合格代理后有界停止；未执行的任务不计作已测试成功或东财 HTTP 失败。表中“触达”包括因取不到代理而没有发出行情 HTTP 的任务。

预热结果也随时间变化：Spys 首次 7 次探测得到 Ready 1；后续源列表刷新失败、缓存过期时出现 0 次探测的供给不足。ProxyScrape 的三代理目标分别出现过 32 次探测、3 次探测、52 次探测、23 次探测才达标，不能将这些轮次相加成独立可用代理数。

初版测试脚本曾在首个业务请求前因为 Python 3.9 不接受 Go 的纳秒 RFC3339 时间戳而退出。该租约已释放，解析已修正并补验 1–9 位小数时间戳；`failover-run-1.jsonl` 是脚本故障诊断，不是行情实验。其旧版汇总中的 `stop_reason=completed` 不表示通过；后续版本已修正异常状态记录。

## 接入前需要处理的事项

1. **现有暗流代理适配器仍是 GET 列表协议。** `backend/internal/proxypool/pool.go` 使用 `http.MethodGet`，当前解析器也不是新服务的 `items/lease/session` 交付协议。仅填写新服务 URL/Token 不能直接复用这次成功路径。
2. **健康代理需要续租。** 普通领取每 30 秒换出好连接，会不断依赖低质量公开列表重新提供好代理。本次成功路径保留健康会话，业务失败才释放绑定换新，同时遵守租约期限。
3. **TLS Ready 不能替代业务成功。** 预热发生在华为云服务器，只完成目标 TLS；行情发生在本机，需要传输真实 HTTP。此前出现的 CONNECT 403 来自代理隧道阶段，不能记成东方财富返回 403。
4. **公网控制面存在连接超时。** 公开 HTTPS API 曾成功创建预热任务，但随后的任务查询和取消请求连接超时。通过 SSH 隧道查询确认该任务实际已经完成。后续实验使用到同一服务 loopback 端口的 SSH 控制隧道；它没有代理或替代股票业务流量。生产接入应单独验证公网控制链路。
5. **Ready 到领取仍需观察。** 普通模式曾在预热 Ready 3 后连续返回 `NO_VALIDATED_RESOURCES`。本次没有证明是选择、缓存/证据变化、并发资格还是代理变化造成，不能只凭该错误断言整个列表没有活代理。
6. **扩量需要真实采集器复测。** 当前实验是本机 curl + 独立 Python 控制器，不是现有 Go 服务或 N1 的运行验收。尚未测试全市场吞吐、数小时连续稳定性、不同交易日和出口环境。

这次结果支持下一步把暗流接入文档化的领取、反馈、失败换绑和健康续租流程，再进行有界扩量测试；暂不支持声称东财风控问题已永久解决。
