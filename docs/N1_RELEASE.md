# N1 上线流程

更新日期：2026-11-08。服务器配置为 `/mnt/data/docker-compose.yml`，本项目服务名为 `shadowflow`。该文件同时管理其它服务，禁止为了本项目上线重建其它容器。

## 先判断数据库影响

对比**当前线上镜像的 revision 到目标镜像 revision**之间的全部变更，不只看最新一条提交。上线记录必须写明数据库影响及备份决定。

| 变更类型 | 上线前数据库备份 |
| --- | --- |
| 前端、样式、只读查询、网络请求、登录逻辑、性能优化等，且不改变数据库结构、持久化格式或已有数据 | **不需要，不执行** |
| 新增或修改表、列、索引、约束、数据库迁移、存储格式、主冷库布局，或随上线执行批量修复、重算、删除等数据改写 | **需要**；启用冷库时主库、冷库成对备份 |
| 仅修改文档 | 不备份，也不为文档更新重启服务或替换线上镜像 |

服务正常连接数据库、记录运行状态或继续原有采集，不等于此次发布有数据库变更。影响不明确时先核查差异，不能默认给每次小修增加全库备份、导出或完整性扫描。

常规定时备份是独立的运维任务，保持原有配置；跳过某次上线前备份不代表停用常规备份，也不新增或修改其计划。

## 发布准备

1. 记录当前镜像固定摘要、revision、Compose、实际生效的任务开关、挂载、端口及容器状态。只记录配置键或脱敏摘要，不输出凭据。
2. 在服务器私有发布目录保存原 Compose，权限设为 `0600`；保留原镜像用于快速回滚。Compose 含真实凭据时不得提交 Git。
3. 确认目标提交的 CI、漏洞扫描和 ARM64 冒烟测试全部通过，取得固定镜像摘要，拉取后核对 `arm64` 架构和 revision。跳过数据库备份不代表跳过这些发布门槛。
4. 核对配置变更白名单。保留服务器既有开关、冷库路径、端口、其它服务和凭据；只有本次明确要求的设置才修改，不用仓库通用默认值覆盖部署方的现状。
5. 依照数据库影响决定是否执行下一节。无数据库变更时直接进入服务更新，不等待或启动新的数据库备份。

## 仅数据库变更执行前置备份

使用当前线上版本的备份脚本，在独立目录生成该批次的前置备份，不影响常规定时备份的留存：

```bash
release_id="$(date +%Y%m%d-%H%M%S)"
docker exec \
  -e "SHADOWFLOW_BACKUP_DIR=/backups/pre-release-$release_id" \
  shadowflow /bin/sh /app/scripts/backup.sh
```

- `SHADOWFLOW_COLD_DATABASE_PATH` 已启用时，脚本自动生成主库/冷库配对的 `.bundle.tar`，不得改成单库备份。
- 等待脚本完整成功，核验清单、完整性检查结果与 `.sha256` 完成标记。不得把仍在生成的暂存文件当作可恢复备份。
- 不直接复制 WAL 模式下的单个 `.db` 文件。磁盘需容纳快照、压缩暂存和最终备份。
- 同一上线批次已有合格前置备份，且尚未执行迁移或数据改写时，不因随后修改非数据库代码、重跑 CI 或重建镜像再次备份。已经执行迁移或数据改写后，重新评估恢复基线。
- 不在盘中为发布反复全库扫描、搬迁或 `VACUUM`。

备份、冷库配对和恢复机制详见 [README](../README.md#备份和恢复) 与 [主冷库实现](database-hot-cold-implementation.md#备份与恢复)。

## 服务更新与验收

将服务器 Compose 中 `shadowflow.image` 改为目标固定摘要，只执行：

```bash
docker compose -f /mnt/data/docker-compose.yml pull shadowflow
docker compose -f /mnt/data/docker-compose.yml up -d --no-deps --pull never shadowflow
```

验收包括：

- `/health/ready`、容器健康状态、重启次数、OOM 与内存占用。
- 实际运行的镜像摘要、revision 和配置是否符合本次变更白名单，其它服务是否保持不变。
- 本次功能的真实服务器请求与页面入口；用小范围只读样本确认既有数据仍可读取。无数据库变更时不额外做全库 `integrity_check`、备份或导出。
- 需要外部账号的功能在服务器环境单独验收；本机登录、模拟数据或 HTTP 200 不代替真实会话、权限与有效数据校验。
- 区分数据的交易日和本次采集时间；周末补齐最近交易日不等于产生了周末行情。

镜像未通过发布门槛、健康异常或配置超出白名单时不宣告上线成功。

## 回滚与记录

无数据库变更的发布失败时，恢复原 Compose/镜像并只重建 `shadowflow`，**不恢复数据库**。涉及数据库变更时按迁移的兼容性决定是否能直接回退代码；需要恢复数据时先停止所有相关写入者，再使用已验证的完整主冷库备份，不能只恢复其中一个库。

上线记录至少保存：代码 revision、CI 链接、镜像摘要、数据库影响、备份跳过理由或备份路径/摘要、配置变更键、验收结果及回滚材料位置。真实账号密码、Cookie、ticket 和会话内容不进入记录正文或 Git。

本次同花顺上线相对于原生产版本包含新的归档/会话表，属于需要备份的发布；同批次后续的登录握手与验证码计算修复不增加第二次前置备份。
