# 东财行情连接故障诊断（2026-11-12）

## 已观察到的事实

生产机LEDE与本机Mac不是同一个HTTP客户端或网络命名空间。生产容器在LEDE上，未配置代理池；LEDE没有公网IPv6地址和IPv6默认路由。Mac的IPv6可达，不代表生产容器可以走同样路径。

当日多次生产机探针能完成IPv4连接与TLS，随后收到空HTTP响应。错误包括curl 52/56、Go EOF和BusyBox wget的`error getting response`。同一容器还能成功请求`stock/get`和`trends2`，因此wget的`Network unreachable`错误文本不能单独证明容器没有IPv4出网。

| 对照 | 本次结果 |
| --- | --- |
| 原家庭IPv4请求`ulist.np/get`与5分钟`kline/get` | 多次空响应 |
| 同一家庭Mac经IPv6请求5分钟`push2his` | 取得过完整48根；其他时段/接口也出现失败 |
| LEDE经IPv6 | 连接失败，设备缺公网地址和默认路由 |
| LEDE经IPv4请求`ulist/get`、`stock/get`、`trends2` | 取得过合法数据，与同出口其他路径失败并存 |
| 切手机热点新IPv4 | 同一组`ulist.np`、`ulist`、5分钟、`trends2`取得合法数据；`stock/get`当次仍空响应 |
| 后续请求 | 原先成功的路径也出现空响应，存在时间与客户端条件变化 |

换网络后的恢复支持出口/网络路径状态是重要因素。上述黑盒对照不能证明服务端只按IP限制、具体QPS阈值、固定冷却时长，或换IPv6就长期稳定。也不能把并发探针后失败的时间先后当成“并发必然封IP”的因果证明。

此前标为“无SNI”的curl命令仍使用域名URL；`--connect-to`不会自动关闭SNI。`--http2`请求若服务器仍协商HTTP/1.1，也没有独立验证HTTP/2。不能据这些实验排除所有客户端/TLS特征。更早的浏览器与普通客户端差异证据仍见 [接口调用记录](EASTMONEY_PUSH2_API.md)。

## 故障影响

本次失败集中在`push2/push2delay/push2his`下的行情接口。东财官网、`datacenter-web`和同花顺公开三池同期取得过正常响应。这是当次可用性观察，不保证以后不会失败，也不证明同花顺普通日/分钟行情已具备完整灾备能力。

当前今日核心真正在线读取为：同花顺三池分页、候选批量行情、粗筛后的逐股暗盘。每批自身历史分位读取是SQLite；`board_ms`段也是本地关系读取，没有调用板块行情缓存。不能用17.8秒`board_ms`证明每次今日核心遍历板块在线采行情，或把另一今日监控的15秒板块缓存当成本接口请求放大的原因。

旧方案每批最多100只、最多预取4批，默认N=20的首个窗口是20+100+100+100只。每批正常一条批量行情HTTP，域名/路径/运输层重试可能放大发送。生产日志能证明某些候选行情失败，尚不能证明今日核心是IP限制唯一触发源。

## 主备与一致性边界

- 批量行情保留`ulist.np/get`主、`ulist/get`备。备用显式带`pn/pz/po/np`。一次12只股票、19个业务字段归一化逐字段比较为零差异；响应的`rt/svr`等元数据不同，不能称两响应字节完全相同，或由有限样本保证所有条件下等价。
- 5分钟以`kline/get?klt=5`为主，失败才用源能返回的窗口内完整241条`trends2`聚合。两者分别记录`stock_kline_5m`与`stock_trends_1m_241`；这是供应商提供的K线数据，不称已直接核实的交易所原始5分钟。
- 旧1分钟聚合数据保留既有来源。股日表重采会更新当前版本，不能由来源字段推导所有历史版本都已永久保留。
- 先前“09:50上游1.62、本地1.60”的所谓舍入差来自诊断脚本误用固定6.25分母；备源实现实际使用上一根收盘，该样例不能证明渠道差异。
- 3000根是项目`maxBars/lmt`预算，不是供应商留存合约。`trends2`的`ndays=5`也不能充当任意久远日期的分钟备源；尚未核实5分钟最早可取日期，不承诺数月/数年都能以后补全。

## 收敛方向

新的 [今日核心设计](today-core-low-request-2026-11-12/design.md) 将普通行情和暗盘移出排名，全部本地候选评分后仅为最终N只补展示行情。三池按日期/scope共享快照，所有实际发送、主备与重试共用预算；行情失败不改变已确定名次。

跨供应商先认证未复权价格/量额/前收与时段。换手、量比、主力资金保留口径，暗盘没有已验证同花顺等价字段。供应商主备、出口可达性与数据库备份是不同故障边界，任何一项都不能单独保证持续可用。

后续诊断使用少量串行对照并记录实际出口、目标IP、HTTP状态、业务完整性、发送数与数据时间；避免高并发反复探测。工程限速与退避是控制负载的措施，不宣称已经发现东财固定限流规则。
