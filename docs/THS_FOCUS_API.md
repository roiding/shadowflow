## 2026-11-13 Web普通行情抓包

来源是用户手动操作同花顺网页，经本机临时代理和独立Chrome采集。网页发出的请求头`Origin/Referer`为`https://stockpage.10jqka.com.cn`，同时携带用户已有登录态Cookie和`x-fuyao-auth`等会话头；这些内容未写入本文件。普通个股样本为`000001`、市场号`33`。页面请求也混有百度财经接口，不属于同花顺主备候选。

共同POST路径：

```text
https://quota-h.10jqka.com.cn/fuyao/common_hq_aggr/quote/v1/single_kline
https://quota-h.10jqka.com.cn/fuyao/common_hq_aggr/quote/v1/multi_last_snapshot
```

`single_kline`请求核心结构：

```json
{
  "code_list": [{"codes": ["000001"], "market": "33"}],
  "trade_class": "intraday",
  "time_period": "day_1",
  "trade_date": -1,
  "begin_time": -400,
  "end_time": 0,
  "adjust_type": "forward",
  "gpid": 1
}
```

网页成功返回的`time_period`有`day_1/min_1/min_15/min_30/min_60`，响应`data_fields`为`1,7,8,9,11,13,19`：依次为时间戳、开、高、低、收、成交量、成交额。`day_1`的`begin_time=-400`返回400根，时间从`2025-03-24`到`2026-11-12`，可见“一次请求可给400根”的边界；不能由此推断任意更早历史或前复权完整性。`min_1/min_15/min_30`的`begin_time=-400`各返回400根。`end_time=0`时页面另发`-1`或`-2`的小窗口请求刷新最新桶。

网页本轮没有实际发出`time_period=min_5`。2026-11-13捕获的1886条HTTP flow中，`single_kline`周期计数为`day_1=45、min_1=12、min_15=33、min_30=3、min_60=8`。随后用抓包中的请求契约做低频直接探测，补验了5分钟：

- `000001`请求`begin_time=-400, end_time=0`返回400根，首根为`2026-11-03 09:45`、末根为`2026-11-13 11:00`；400根是“最新400根”而非从窗口起点补齐的完整历史，首日最早两个5分钟桶被截掉。
- `000002`用另一请求体返回10根/12根5分钟K，排除只命中`000001`缓存的解释。
- 5分钟桶时间戳间隔为`300`秒；午休跨度为`5700`秒，隔夜跨度为`66900`秒。探测时本机时间为`10:58`，响应最后一根时间戳已标为`11:00`；因此不能把最后一根当作已完成的11:00桶。时间戳究竟是桶起点、桶终点还是未完成桶的预定标签，需再结合成交量和收盘后结果确认，当前不据此计算未来成交。
- 复权参数在页面默认配置中为`forward`，枚举另有`backward`和`actual`。实测`actual`为不复权：`000001`在2025-03-24的日收盘为`11.38`，同一行`forward`为`10.173`，最近交易日两者一致。项目备源使用`actual`，避免跨除权日后把前复权序列写入未复权归档。5分钟更早分页边界仍需按实际保留窗口处理。

认证对照在低频、每次间隔2秒、不同请求范围下进行，先以完整会话取得对照成功，再测试5分钟：

| 发送内容 | HTTP/业务 | 结果 |
| --- | --- | --- |
| Cookie + `x-fuyao-auth` | 200 / `ok` | 400根5分钟 |
| 仅Cookie | 200 / `ok` | 50根5分钟 |
| 仅`x-fuyao-auth` | 200 / `ok` | 60根5分钟 |
| 两者都不带 | 200 / `ok` | 70根5分钟，`000001` |
| 两者都不带，另一只股票 | 200 / `ok` | 10根5分钟，`000002` |
| 仅`Content-Type`、另一只股票 | 200 / `ok` | 12根5分钟，`000002` |

因此就本次直接HTTP请求而言，Cookie、`x-fuyao-auth`、`Origin`和`Referer`都不是必需条件；用户已有登录态不影响这一结论，但浏览器页面仍会携带它们。结论仅适用于当前日期、路径、请求体和出口；不能据此承诺永久匿名、无限额度或不会触发频控，也不能把去掉会话头解释为可绕过未来的授权要求。生产适配器仍应保留会话注入能力、共享限速、熔断和明确失败状态。

## 官方登录流程

已直接读取官方登录页及其公开脚本，确认：

1. 登录页：`https://upass.10jqka.com.cn/login`。
2. 公钥：`GET /pubkey/default.js`，提供RSA版本、模数和指数。
3. 盐值：`POST /user/getGS`，提交加密用户名、公钥版本与随机数。
4. 密码登录：`POST /login/dologinreturnjson2`。用户名和密码摘要经RSA加密，`passwdSalt`遵循官方SHA256/HMAC及盐值处理。服务端可能要求第二步盐值交换。
5. `errorcode=0`后还检查私有图表配置接口，确认新Cookie能读取账号数据，再作为有效会话保存。

官方密码页面明确拒绝手机号、邮箱作为用户名；这两类登录需要走短信或其他交互流程。已验证的滑块挑战支持有界协议处理；验证码未通过、设备处置、账号拒绝、弱密码修改要求均进入需要人工处理状态，不无限重试。密码本身不会写入日志或接口响应。

### 自动登录与请求重试

账号接口统一经过会话管理器。HTTP401、指标查询的业务401，以及已验证的私有图表配置`status_code=-2`触发过期处理；权限查询只将实测的“需要授权”响应识别为登录失效，普通“无权限”、403、429、网络错误不触发密码登录。一个刷新任务为并发请求共享；已经完成刷新后才到达的旧401复用新会话。登录成功后原请求最多重放一次，再次失效即返回错误。数据查询POST保留原始URL、请求体与业务参数，重试不更换股票或交易日。

刷新失败默认冷却5分钟；错误密码、未解决的验证码与设备确认要求停止自动密码重试，等待显式`ths-login`或更新会话。一个等待者取消不会中断其他等待者的刷新，关闭管理器会取消其网络请求与刷新任务。会话只发往固定的同花顺数据域，重定向不会携带凭据跟随到其他站点。登录态默认写入应用数据库`ths_session`表（数据库文件收紧为0600），也可用`SHADOWFLOW_THS_SESSION_FILE`改回私有文件模式；两种模式都保留Cookie的域、路径、Secure及到期信息，响应中的Cookie轮换和删除同样持久化，Max-Age转换为绝对到期时间，重启不会延长其寿命。2026-11-08已由本机连接真实同花顺接口验证完整链路：无头浏览器握手（10个握手Cookie）+密码协议+滑块伪造+重提交全部成功，凭据正确时服务端返回`errorcode=0`；这不替代Linux容器上的独立验收。

常驻管理器在账号请求前及认证失效后检查共享会话内容。另一个进程完成`ths-login`后，下一次请求采用新会话并清除旧的人工处理状态，无需重启；相同的旧会话或已过期Cookie不会解除密码重试停止状态。旧请求准备持久化Cookie轮换时也会检查共享会话，发现新会话便放弃旧响应回写。选择`SHADOWFLOW_THS_SESSION_FILE`后，CLI与服务均使用该文件，文件缺失不会悄悄回退到数据库；文件模式的登录与状态命令不要求打开应用数据库。

浏览器握手要求成功导出非空且稳定的同花顺Cookie集合，使用该集合中最新的`v`。首次观察到有效`v`后至少等待10秒，并要求连续两个750毫秒轮询间隔集合不变；稳定阶段最多20秒，避免设备Cookie延迟6–10秒时被早期短暂静默误判完成。CDP错误、导出失败、空集合、取消和超时均返回握手失败，不能只因先前页面出现过`v`就继续密码提交。登录成功验收仍须与账号指标有效性、Linux容器运行验收分别记录。

滑块图像匹配预计算灰度、透明掩码与模板统计量，搜索窗口不再反复分配像素数组；保持原Pearson阈值、坐标和请求参数口径。匹配过程检查取消，解码前限制图片像素数，避免低功耗服务器的计算耗时挤占登录超时预算。

配置项：

| 环境变量 | 默认 | 用途 |
| --- | --- | --- |
| `SHADOWFLOW_THS_AUTO_LOGIN` | `true` | 账号数据请求失效后自动登录；要求凭据与无头浏览器配置齐全 |
| `SHADOWFLOW_THS_USERNAME` / `SHADOWFLOW_THS_PASSWORD` | 空 | compose 环境变量凭据（`docker inspect` 可见，部署方接受此取舍）；与凭据文件二选一 |
| `SHADOWFLOW_THS_CREDENTIALS_FILE` | 空 | 私有JSON文件，字段`username/password`（开发模式） |
| `SHADOWFLOW_THS_SESSION_FILE` | 空 | 私有持久会话文件；设置后优先使用文件，不设置时入库 |
| `SHADOWFLOW_THS_HEADLESS_BROWSER` | `/usr/bin/chromium-browser` | 无头浏览器路径；容器镜像已内置 Chromium 与 CJK 字体 |
| `SHADOWFLOW_THS_CHROME_ARGS` | 容器内 `--no-sandbox --disable-dev-shm-usage` | 浏览器附加启动参数 |

本地开发或临时录入凭据（文件模式）：

```sh
python3 scripts/ths_credentials.py /absolute/private/ths/credentials.json
cd backend
SHADOWFLOW_THS_AUTO_LOGIN=true SHADOWFLOW_THS_CREDENTIALS_FILE=/absolute/private/ths/credentials.json SHADOWFLOW_THS_HEADLESS_BROWSER=/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome go run ./cmd/collect -task ths-login          # 登录态写入数据库
SHADOWFLOW_THS_AUTO_LOGIN=true go run ./cmd/collect -task ths-auth-status
SHADOWFLOW_THS_AUTO_LOGIN=true go run ./cmd/collect -task ths-account-data -date 2026-11-06 -codes 33:002578,17:603381
```

线上部署不再需要挂载凭据或会话文件：凭据由 compose 环境变量提供，登录态保存在 `/data/shadowflow.db` 中并跨进程共享。每日盘后调度：`end-of-day-events`（涨停事件）在 `16:30/16:35/16:40`，同花顺题材补充 `ths-focus` 在 `16:45`，受限账号数据 `ths-account-data` 在 `16:50/17:10/17:50` 自动按当日涨停名单分批（每批≤20只）采集入库；个股五分钟 K 从 `17:00` 起，排在上述同花顺任务之后。不要把真实密码放进 Git 或聊天记录；compose 环境变量的可见范围由部署方自行评估。

账号调度只在服务实际接入账号数据源后启用，并继续尊重事件开关、`ths-account-data`及父级`end-of-day`的禁用配置。未配置凭据/浏览器或未开启自动登录时，不排队也不领取旧账号任务，公开事件归档仍可独立运行。上表的自动登录默认值指Compose配置；直接运行Go程序时默认`false`。
