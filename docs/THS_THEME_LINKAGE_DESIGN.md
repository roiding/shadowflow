# 同花顺题材历史聚类与股票联动设计

状态：已实现代码，未发布生产。本文替代早期“昨日 Top20 验证今日主线”的草稿口径。

## 核心口径

同花顺涨停简图的 `tab_list + all_tab_data` 每天返回源整理好的分类及分类成员。`block_top` 只是普通 Top20 板块榜，**不是**涨停简图分类。真正用于股票聚类的是**按历史日期累积的涨停简图分类多标签体系**：

- 某只股票在某天进入某个涨停简图分类，就为该股票积累该分类标签。
- 同一股票可以在不同日期积累多个题材标签，因为不同阶段的涨停原因可能不同。
- 标签按 `trade_date` 使用，不按回补时的 `fetched_at` 使用。
- 当日盘后分类不能在盘中偷跑；今日核心只使用今日之前最近完整事件归档日及更早的标签。
- 东财行业/概念不参与股票聚类和今日主线。缺失涨停简图标签时明确显示“标签不足”，不做东财兜底。

### 未分类题材桶

涨停简图中可能出现没有明确原因的残留分类，例如“其他概念”“未分类”“原因不明”，或某个分类下全部股票都没有 `reason/abnormal_reason/detail_reason`。这些桶不能把所有没有原因的股票强行聚成一类：

- 入库时把分类名称命中未分类词的行标记为不可用。
- 入库时把全组股票都没有明确原因文本的分类标记为不可用。
- 聚类计算层再次过滤，防止调用方绕过入库过滤。
- 同一有效板块内个别股票缺少原因文本时，仍保留板块级标签；板块本身已经有明确分类。

## 数据表

原始证据仍保存在 `ths_focus_day.payload_json`。新增分类原始投影表：

`ths_theme_tab_day(source, scope, trade_date, tab_name, tab_rank, stock_count, usable, fetched_at)`

`ths_theme_tab_stock(source, scope, trade_date, tab_name, tab_rank, stock_code, stock_name, market_id, reason, abnormal_reason, detail_reason, usable)`

- 主键：`(source, scope, trade_date, tab_name, stock_code)`。
- 每个分类-股票-交易日一行，保留源分类原名和源原因字段。
- `tab_rank` 保留源分类顺序，后续可用于排名衰减权重。
- `usable` 过滤“其他概念”等残留分类；原始行仍保留，避免丢失证据。
- 旧 `ths_theme_stock_day` 仅保留为历史 block_top 派生表，不再作为聚类读取来源。
- 由 `SaveThsFocus` 在同一事务内同步维护；首次启动时从已归档 payload 回填一次，并有完成标记。

## 股票画像

对窗口内每只股票聚合出：

- 每个分类的出现次数、首次日期、最近日期、近 60 日出现次数。
- `label_days`：至少进入一个有效涨停简图分类的交易日数。
- 多标签按集合处理，不把同一天多个题材重复算成多天。

### 同题材联动

对中心股票 A 和候选 B：

- `theme_days`：同一天进入至少一个相同题材的天数，按日期去重。
- `shared_themes`：共享过的题材标签。
- `theme_jaccard = theme_days / (A标签日 ∪ B标签日)`。
- `theme_similarity`：把每只股票的题材出现次数按 IDF 加权后做余弦相似度。常见大题材权重更低，避免“机器人/人工智能”等大标签把全市场连在一起。
- `co_seal_days`：同日收盘封板次数；若原始共现边被阈值截断，仍以同题材日数作为下限。
- `theme_purity = theme_days / co_seal_days`：同日封板中有多少至少共享一个题材，用于识别跨题材普涨共振。
- `last_shared_date`：最近一次同题材共同出现的日期。

原始全市场同日封板共现仍然保留，但 UI 明确标为“全市场同日共振”，不再与同题材联动混称。

## 今日涨停核心

今日核心使用实时封板快照，不使用今日盘后分类：

1. 读取点击时仍封住涨停的今日成员。
2. 为每个成员读取今日之前历史窗口内的涨停简图分类累积标签。
3. 成员核心度 = `35% 关系强度 + 25% 关系覆盖 + 20% 邻居强度 + 20% 同题材聚类`；同题材聚类按成员与今日其他成员共享标签的 IDF 加权强度计算，因此没有历史共封边但同题材的成员仍可进入核心排序。
4. 对每个题材统计共享该标签的今日成员数；至少 2 只成员共享才进入实时主线。所有满足条件的主线分别保留，不合并成单一主线。
5. 主线权重 = 成员核心度加权 × 题材 IDF × 时效 × 封板质量；返回最多 12 个题材。时效 = `e^(-Δt/90) + (1-e^(-Δt/90)) × n/(n+5)`，`Δt` 是该主线当前封板成员最近一次封板（回封会刷新）距快照的交易分钟数，午休不计入；`n` 只统计当前仍封板且共享该题材的成员，不含未涨停或炸板股。封板质量 = `封板 / (封板 + 0.5 × 炸板 + 1 × 跌停)`，炸板和跌停取当前实时侧池，分别按半个和一个封板损失扣减。历史标签的最近出现日期不参与主线权重；它只用于展示标签历史，不会把“近期涨停次数”直接加到候选分。个股没有有效历史标签时，才使用本地东财概念/行业关系兜底，并按可识别的名称映射到同花顺题材；不解析盘中自由文本 `reason`。
6. 每条主线独立给候选：单主线贴合 = `主线权重 × (o+r)/(o+r+2)`，其中 `o` 是该候选在该题材的历史出现次数，`r` 是近60日出现次数；近期出现额外计一次。跨主线共振 = `1 - Π(1 - 单主线贴合)`，同时命中多条主线时收益递减，不再使用最强80%+次强20%。面板最终将候选去重，只展示一张统一结果表。
7. 候选排序先算全量候选的主线项、历史特异性和关联覆盖，再按“盘中确认满分且无风险折价”的理论上界从高到低分批读取盘中行情和自身历史。每批算出不含暗盘的真实分后，只有当前第 N 名的真实分严格高于所有未取数候选的上界加暗盘最大增量才停止；同分继续读取，不能提前截断。粗筛结束后，只对仍可能进入前 N 的少量候选请求一次暗盘资金；暗盘超时或部分失败时降级为不含暗盘的结果并标记状态，不阻塞整批。前端只展示去重后的统一候选结果集，不再按主线展开多张候选表。
8. 有实时行情时，候选分 = `100 × (30% 盘中承接 + 40% 主线项 + 20% 历史特异性 + 10% 关联覆盖) × (1 - 最多15%风险折价)`。单主线组内使用该主线的贴合分，跨主线表使用多主线共振分。历史特异性仍用 φ 扣除双方封板频率；股票自身近一年涨停次数不直接加分。
9. 盘中承接 = `启动承接30% + 剩余空间20% + 换手自身历史分位15% + 量比10% + 主力资金自身历史分位10% + 暗盘资金自身历史分位15%`，缺少数据时按可用项重新归一化；换手、主力和暗盘资金按个股最近20个交易日同一5分钟时点的自身历史计算，量比直接使用东财自身基准值，不拿不同股票横比。暗盘只对粗筛后的少量候选请求，不参与每批粗筛。已触板但当前未封扣 20%，不把接近涨停或触板当成正向加分。涨停空间按主板普通与主板 ST 10%、创业板/科创板 20%、北交所 30% 计算；触板按前收四舍五入后的涨停价判断。风险扣分 `risk_penalty=(1-risk_score)×100` 逐行展示，综合分只做最多 15% 折价。
10. 行情不可用时，实时项退出、其余三项重新归一化，并在接口和界面明确标记“仅历史观察”；缺少行情不能伪装成盘中确认。
11. 额外加入“只有同题材标签、没有直接共封边”的候选；这类候选的 `effective_links` 和 `strength` 为 0，只拿主线分，不能伪装成强历史关系。
12. 今日盘中快照与候选行情不写入历史事件表，也不进入历史分母。

候选列表仍按打分从高到低展示，不收敛成单只“可买”结论；最终由用户人工确认。

## 股票联动页

- 支持六位代码、中文名称、拼音首字母/全拼直接搜索。
- 展示中心股票的历史累积涨停简图分类标签、同题材联动表、全市场同日共振表、股性画像和历史事件明细。
- 回看窗口、市场范围、共现事件、最少协同次数和展示数量均可调整。
- 今日监控、收盘个股、动态筛选的“联动/股性”快查复用同一套参数和口径，并显示实际样本截止日。
- 所有统计字段使用小问号解释；涨停简图分类、盘后整理、回补数据、非完整成份等限制在页面明确标注。

## 限制

- `tab_list/all_tab_data` 只覆盖源已归类的涨停股，不是完整行业/概念全集；部分股票可能没有任何有效标签。`block_top` 不能用于补造分类。
- 同花顺题材是盘后整理口径，盘中不可用；历史回补快照的 `fetched_at` 不是当时可知时间。
- 题材代码/名称可能变化，以代码为主、名称为辅。
- 同题材只提高聚类置信度，不等于因果、带动或未来收益。
- 未分类桶被排除，但有效板块仍可能包含宽泛题材；IDF 只能降权，不能把宽泛题材变成精确产业链。
