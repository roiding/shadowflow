# 同花顺涨停聚焦：联动性与股性研究数据源评估

核查日期：2026-11-05，时间口径为 Asia/Shanghai。

## 结论

同花顺手机端涨停聚焦可作为第一版“涨停共现网络 + 个股涨停行为”研究的候选主数据源。已通过真实首屏 HAR 定位接口，并以不携带账号 Cookie、Token 的 HTTP 请求取得当日和历史样本。2026-11-05、2025-11-05 两日的涨停池与炸板池均完整取得，唯一股票数、分页总数和触板汇总相符。

这证明当前接口具备所需的数据和读取能力，不代表已完成连续一年数据的完整性验证或长期运行验证。两三年前的抽查日期被接口明确拒绝；当前最早成功样本为 2025-11-04，尚未确定精确历史边界。

研究初期无需购买全市场逐笔数据。该源提供日级事件结果、开板次数、首次/最后涨停时间等现成字段；若研究精确开板、回封过程与秒级领先关系，仍需额外的完整事件流或更细粒度行情。

## 接口与分页

接口根路径：`https://data.10jqka.com.cn/dataapi/limit_up`。

| 路径 | 功能 | 验证程度 |
| --- | --- | --- |
| `/limit_up_pool` | 涨停池 | HAR、当日完整数据、多个历史日期、第二页均验证 |
| `/open_limit_pool` | 炸板池 | 当日和一年前两日完整数据验证 |
| `/continuous_limit_pool` | 连板池 | 公开前端标签和路径拼接确认，未请求 |
| `/lower_limit_pool` | 跌停池 | 公开前端标签和路径拼接确认，未请求 |
| `/limit_up` | 冲刺涨停 | 公开前端标签和路径拼接确认，未请求 |
| `/trade_day` | 交易日历 | HAR 有真实响应；不代表对应日期一定有榜单数据 |
| `/trade_status`、`/v1/trade_status` | 当前交易状态 | HAR 有真实响应 |
| `/change` | 最新异动 | HAR 只请求 `type=latest`，不能视作完整历史事件流 |

首屏请求参数：

```text
page=1
limit=15
field=199112,10,9001,330323,330324,330325,9002,330329,133971,133970,1968584,3475914,9003,9004
filter=HS,GEM2STAR
date=20261105
order_field=330324
order_type=0
```

首屏响应 `data.page` 为 `{"limit":15,"total":83,"count":6,"page":1}`，`data.info` 只有 15 条。第二页返回另外 15 只，与首屏无重叠。`count` 是总页数。

额外测试 `limit=100` 成功：当日 83 只涨停、47 只炸板各用一页取全。100 不是已证明的接口最大值；以后仍须根据总数和页数循环，不能将首屏或一页当成完整数据。

`field` 是逗号分隔的字段 ID，JSON 返回可读字段名。不同页面表格可能复用数字 ID，不能脱离当前接口硬套字段字典。

成功样本都核对了响应交易日期，以及个股首次涨停 Unix 时间戳转换后的本地日期，与请求日期一致，没有仅凭 HTTP 200 判断成功。

两三年前请求被拒绝不代表同花顺没有更早原始数据，只说明本次接口及参数组合不接受这些日期。

## 市场范围

| 筛选值 | 页面含义 | 实测情况 |
| --- | --- | --- |

| `GEM2STAR` | 创业板/科创板 | 实际返回 `GEM` 和 `STAR` |

2026-11-05 使用 `HS,GEM2STAR,ST,NEW`，完整返回 85 只涨停，比默认范围多 ST百利、*ST亿晶两只；触板汇总 133，炸板汇总 48。该扩大范围的炸板明细未另行请求。

未发现本页面北交所筛选项，也没有取得北交所样本，不能将该源的默认榜单直接称为“全 A 股”。建议保留市场、ST、新股等状态；若要纳入北交所，另行补源与验收。

## 可用于研究的字段

| JSON 字段 | 当前页面含义 | 使用注意 |
| --- | --- | --- |
| `code`、`name`、`market_id`、`market_type` | 股票身份及市场 | 股票代码作为字符串；同花顺市场 ID 不能直接用作东财市场 ID |
| `first_limit_up_time` | 首次涨停时间 | Unix 秒，本次为字符串；转换到 Asia/Shanghai |
| `last_limit_up_time` | 最后涨停时间 | 不包含所有开板、回封时刻 |
| `open_num` | 开板次数 | 有 `null`，必须保留原始缺失，不能未经核实改成 0 |
| `limit_up_type` | 涨停形态 | 如换手板；保留源标签 |
| `high_days` | 几天几板 | “5天4板”不能当成“4连板” |
| `is_again_limit`、`change_tag` | 回封相关标记、异动类型 | 先作为源字段保存；未证明可完整替代开板次数 |
| `limit_up_suc_rate` | 近一年涨停封板率 | 返回小数，如 0.625；历史查询时的统计截止日尚未验证 |
| `order_amount`、`order_volume` | 封单额、封单量 | 快照字段，不是逐笔撤单、委托变化历史 |
| `latest`、`change_rate`、`turnover_rate` | 价格、涨跌幅、换手率 | 两个比率样本为百分数数值，不能和封板率小数混用 |
| `reason_type` | 涨停原因标签 | 可用于解释关系；不应作为构图的硬性板块限制 |
| `currency_value` | 页面实际流通字段 | 做市值分层前复核单位及精确定义 |
| `time_preview` | 分时预览 | 首屏每股只有 80 个值，无逐点时间戳，不能当完整分钟或逐笔行情 |

首屏示例：征和工业 `003033`，首次涨停 09:46:45，最后涨停 14:56:03，`open_num=12`，`high_days="2天2板"`，近一年封板率字段 0.625。它收盘仍在涨停池，但当天发生过开板。

## 必须区分的事件口径

2026-11-05 默认范围：

- 收盘涨停池 83 只。
- 炸板池 47 只，表示触及涨停后最终未留在涨停池的股票集合。
- 两池并集为 130 只，与 `limit_up_count.today.history_num=130` 一致。这里的 `history_num` 是当天累计触板数，不是历史一年累计股票数。
- 涨停池中另有 35 只 `open_num>0`，因此 47 只炸板池股票不等于“当天所有曾经开板的股票”。其余 48 只的 `open_num` 为 `null`。
- 此样本至少有 82 只股票出现正开板次数；在确认 `null` 含义前，不把 82 当作精确的全体曾开板股票数。
- 页面封板率 83/130≈63.85%；这是当日截面的最终封板比例，不等于个股 `limit_up_suc_rate`。

建议分开保存“曾触板”“收盘涨停”“触板未封住”“开板次数”等字段。盘后还可由涨停池成员身份和正开板次数识别“开板后最终回封”，但这不能重建每次回封的顺序和持续时间。

本次 `time_preview` 也有末值与 `change_rate` 不相等的样本，进一步说明它是预览数据，不能用于精确判断收盘状态。

## 接入建议

1. 先建立每日个股事件表，保留日期、身份、市场范围、所属池、开板次数、首末时间、形态、原始原因标签和采集时间；同时保存来源、请求筛选参数和完整性状态。
2. 首批回补目标设为近一年。按交易日获取涨停池、炸板池；逐日核对日期、分页、唯一代码、池间交集和汇总数量。失败、无交易和真实空榜单分别处理。
3. 每天盘后采集并在本地长期累积。当前源的历史窗口有限，漏采后能否补回取决于上游保留范围。
4. 使用现有个股日线、五分钟行情和资金归档作为增量分析基础。历史研究还需股票上市/退市/停牌/ST 状态、交易日历，以及相应期间的日线和涨跌停价格；不能把缺数据都记作“未涨停”。
5. 涨停判断使用未复权价格与当日真实涨停价，不能统一套“涨幅≥9.9%”。收益研究另用适当的复权或公司行动处理。
6. 联动计算先保存每日事件矩阵，不必每天物理保存所有股票对。按滚动窗口计算共现、条件概率和相对基准的提升；调整个股自身涨停频率、市场整体涨停热度，并设置最低共同样本数与样本外验证。
7. 近一年封板率等派生统计建议用本地、当时已发生的事件重算。源字段可留作核对，但未确定历史统计截止日前，不直接用于历史预测特征。
8. 完整日榜单稳定采集后，再考虑精细事件时间线、分钟领先关系、封单持续性。现有 80 点预览不能替代这些数据。

两池每天通常是少量分页，远小于全市场逐股逐笔抓取；这适合先验证研究价值。图计算和历史分析在本地离线进行，避免在现有采集设备上执行大范围重查询。

## 尚未验收

- 连续近一年所有交易日和所有分页的完整性；这里只完成跨日期抽样和两天双池完整核对。
- 后端精确历史起点、超窗错误的长期一致性，以及不同时段、不同网络下的稳定性。
- 北交所覆盖、退市股票历史保留、ST 变更时的历史筛选口径。
- `open_num=null` 的完整含义、开板计数的采样规则、集合竞价处理、源数据修订策略。
- 历史请求中 `limit_up_suc_rate` 等派生字段是否严格只用当时已知数据。

HAR 的 `startedDateTime` 文字时区与同一响应的 HTTP Date、业务时间戳存在约 8 小时偏差。交易时刻以接口 Unix 时间戳转换结果和响应交易日期为准，不能直接使用该 HAR 导出字段为事件定时。
